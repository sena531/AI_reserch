## 全体の並びと理由

```c
void control_isr(void)
{
    /* ① センシング */
    /* ② 極性判定（ヒステリシス付き） */
    /* ③ 健全性チェック・保護 */
    /* ④ 外側ループ（N 回に 1 回） */
    /* ⑤ 乗算器 → 電流指令 */
    /* ⑥ 電流 PI */
    /* ⑦ フィードフォワード加算・クランプ */
    /* ⑧ ゲート配分 */
}
```

**③ を ⑥ より前に置く。** 壊れた入力で制御器を回すと、積分器が異常値を記憶する。
一度巻き上がった積分器は、原因を取り除いたあともしばらく悪さをする。

**⑧ を最後に置く。** 途中で `return` して抜けると、前回のデューティが残り続ける。
ハードウェアは止まらないので、「制御が止まったのにスイッチングは続く」最悪の状態になる。
保護がかかったときも、`return` ではなくフラグを立てて最後まで流し、⑧ でゼロを書く。

## センシングと極性判定

### 交流を片側ずつ検出する構成

ブリッジレス構成では、L 側と N 側の電圧をそれぞれ GND 基準で測る。
どちらか片方だけが立つので

```c
Vac  = ADC_L - ADC_N;   /* 符号付き。極性判定に使う */
Vrec = ADC_L + ADC_N;   /* |vac|。乗算器と FF に使う */
```

この構成は「反対側がボディダイオードで GND にクランプされる」ことを前提にしている。
**電流が流れていないとクランプが成立せず、読み値が正しくない。** 無負荷での校正値を
そのまま定格に使うと合わないことがある。

### ヒステリシス

零クロス付近でチャタリングすると、ゲート配分が高速に反転して危険。

```c
if (half) { if (Vac < -VAC_HYST) half = 0; }
else      { if (Vac >  VAC_HYST) half = 1; }
```

`VAC_HYST` はオペアンプのオフセットとノイズより十分大きく取る。小さすぎると、
入力が無いのにオフセットだけで極性が決まってしまう。

### 整流座標への折り返し

```c
if (half) { Ir =  Iin; } else { Ir = -Iin; }
```

**ここが符号規律の要。** `Iref` は常に正（整流座標）なので、`Ir` も同じ座標でなければならない。
極性フラグがずれると `Ei = Iref − Ir` の符号が反転し、**負帰還が正帰還になる**。

症状は「デューティが上限に張り付いて動かない」「実電流が指令の数倍」。
ゲインの問題と区別がつきにくいので、物理的にありえない値を検出する関門を置く。

```c
/* 昇圧形はダイオードが逆流を阻止するので、整流座標の電流が
 * 大きく負になることはありえない */
if (Ir < -NOISE_BAND) { pol_err = 1; Ui = 0; Ei_1 = 0; }
```

**極性判定とゲート配分は同じ判定から導く。** 別々の条件式で書くと、
零クロス付近で「ゲートは正の半周期、電流の符号は負の半周期」という瞬間が生じる。

## 外側ループを間引く

電圧ループは商用周波数で回せばよいので、カウンタで間引く。

```c
vo_sum += Vo_adc;
if (++scan_cnt >= N_VLOOP) {
    scan_cnt = 0;
    Vo_avg = (int)(vo_sum / N_VLOOP);
    vo_sum = 0;
    /* ここで電圧 PI を 1 回だけ回す */
}
```

積算と間引きを同じカウンタでやると、**移動平均の窓幅とループ周期が自動的に一致する**。
別々に持つと、ずれたときにリプルが漏れる。

`N_VLOOP = fs / f_line` を `#define` で導出すること。直接数値を書くと、
商用周波数を変えたときに窓幅だけ取り残される。

### モード切替時の初期化

開ループ↔閉ループを切り替えるなら、**積分器を現在値に合わせてから**切り替える。

```c
Uv   = (int32_t)Ipk << SH_V;   /* いま出ている指令に合わせる */
Ev_1 = 0;
vref_init = 1;                 /* 目標値も実測値から立ち上げる */
```

これをやらないと、切り替えた瞬間に指令が飛ぶ。

## ゲート配分

```c
if (fault) {
    PDC1 = 0; PDC2 = 0;
}
else if (Vac >= VAC_HYST) {       /* 正の半周期 */
    PDC1 = Wout; PDC2 = 0;
}
else if (Vac <= -VAC_HYST) {      /* 負の半周期 */
    PDC1 = 0;    PDC2 = Wout;
}
else {                            /* 零クロス近傍 */
    PDC1 = 0;    PDC2 = 0;
}

if (sensor_bad) { PDC1 = 0; PDC2 = 0; }   /* 後段で上書き */
```

**どちらか一方は必ず 0 になる。** デバッガで停止して両方 0 でも、
零クロス付近を掴んだだけかもしれない。瞬時値で判断しないこと。

### 相補モードの注意

相補出力（PMOD = 0）にすると、`PDC = 0` のとき**ロー側が 100% オン**になる。
休ませたい側のスイッチを「常時オフ」にしたいなら、ロー側の出力を配線してはいけない。
配線すると同期整流動作になり、意図した動作と変わる。

スコープで「信号が出ていない」と判断するときも、
**ハイ側だけでなくロー側も見る**。常時 Hi ならデューティ 0、何も出ていないなら配線かピン設定。

## ADC トリガ位置

トリガ位置が「電流」という言葉の意味を決める。

| 位置 | 読めるもの |
|---|---|
| スイッチング周期の境目 | **最悪**。ターンオンのリンギングを電流値として読む |
| オン期間の中ほど | CCM なら平均電流の良い近似 |
| オフ期間 | スイッチ電流ではなくダイオード電流（構成による） |

PWM の立ち上がり、立ち下がり、他チャネルのエッジが重なる点を避ける。
周期の 20〜30% あたりが無難なことが多い。

### DCM では 1 点サンプリングが成立しない

不連続モードでは電流が毎周期ゼロから立ち上がってゼロに戻る。
サンプル点がパルスの外に落ちれば 0 と読み、**ループは「電流が足りない」と判断して
デューティを上げ続ける**。実電流が指令を大きく超える。

軽負荷・低入力電圧で挙動が理解できないときは、まず CCM かどうかを確かめる。
CCM にするには負荷を重くするか、インダクタンスを増やすか、周波数を上げる。

## 保護の層

| 層 | 速さ | ノイズ耐性 | モード |
|---|---|---|---|
| アナログ比較器 | サブ µs | 低い | **サイクルバイサイクル制限** |
| ADC + ソフト判定 | 1 周期 | 高い | **ラッチ停止** |
| 妥当性チェック | 遅い | — | 制御を禁止 |

### 比較器をラッチにしない

アナログ比較器は連続監視なので、ADC が見逃す細いスパイクも拾う。
これをラッチ停止にすると、**ノイズ 1 発で装置全体が止まる**。
サイクルバイサイクルなら該当周期だけ削れて次から復帰する。

### ソフト側は多数決で

単発のサンプルでラッチしない。2 回以上連続で成立したときだけラッチする。

```c
if (over_current) { if (++ocp_cnt >= 2) fault = 1; }
else              { ocp_cnt = 0; }
```

ADC サンプリングが 1 周期に 1 回なら、2 回で 20 µs。その間に電流が進む量を見積もって、
許容できる範囲か確認する（`di/dt = V/L`）。

### 段をまたいで止めない

二段構成で、**入力側の過電流で後段まで止めると中間コンデンサが過電圧になる**。
正しい動作は「前段を絞って入力を断ち、後段は回したまま中間電圧を抜く」。

### アナログ側で先に手を打つ

「比較器がノイズで誤トリップする」を**ソフトのしきい値調整で追い込もうとしない**。
原因はたいていアナログ側にあり、そちらを直すほうが確実で速い。

**① リーディングエッジブランキング（LEB）**

ターンオン直後には、ダイオードの逆回復電流、出力容量 `Coss` の充放電、
配線容量を通る変位電流が重なって、電流センスの頭に**数十〜数百 ns の針**が立つ。
これは本物の電流ではないので、**窓から外す**のが正しい扱い。

LPF で潰そうとすると遅延がそのまま保護の応答遅れになるので、**フィルタではなくブランキング**を使う。
dsPIC33 なら `LEBCONx` の `FLTLEBEN` / `CLLEBEN` と `LEBDLYx`。200〜400 ns から始めて、
実測のスパイク幅の 1.5 倍を狙う。

**最小オン時間 > LEB 時間** は必須。これを破ると、細いパルスの周期だけ保護が無効になる。

**② 比較器のヒステリシス**

`HYSSEL` / `HYSPOL` でヒステリシスを最大に。しきい値付近での再トリガが止まる。
内蔵していない品種なら、外部に正帰還抵抗を入れる。

**③ 二段しきい値**

多くの DSC は「電流制限（Current-Limit）」と「フォルト（Fault）」を**別系統**で持つ。

| 系統 | しきい値 | 動作 |
|---|---|---|
| Current-Limit（`CLSRC`/`CLMOD`） | 低め | サイクルバイサイクルで切る |
| Fault（`FLTSRC`/`FLTMOD`） | 高め | ラッチ停止 |

比較器を 2 個使えるなら、低い方を Current-Limit、高い方を Fault に割り当てる。
1 個しかないなら Current-Limit に使い、ラッチはソフト側に持たせる。

**④ 入力側の RC**

比較器入力の RC は**遅延がそのまま保護の応答遅れ**になるので、数十 ns までに抑える。
スパイク対策は RC ではなく LEB の仕事。

**⑤ センスの引き回し**

シャントならケルビン接続（パッドの内側から 2 本）。センス配線はパワーループと
ゲートループをまたがない。比較器の基準電圧がどの GND を参照しているかを確認する。

切り分けとして、**ターンオン側のゲート抵抗を上げて `dv/dt` を下げると消えるか**を見ると、
ノイズ起因かどうかが一発で分かる。

### デューティの更新は原子的に

2 つのレジスタ（例 `PDC1` と `PDC2`）に別々に書くと、その間に周期境界が来たとき
**片方が旧値、片方が新値で 1 周期動く**。たいていは無害だが、相補動作やブリッジでは
異常パルスになり、それ自体が比較器をトリップさせる。

- バッファ更新（`IUE = 0` 相当）になっているか確認する。即時更新だと周期の途中で変わる
- マスターデューティ（`MDC` + `MDCS`）が使える構成ならそちらで一度に書く
- どうしても 2 回書くなら、**周期境界から遠いタイミング**で書く

### 妥当性チェックは積算で

「N 回連続で範囲内なら健全」は、N の間に単発ノイズが 1 回入ると振り出しに戻る。
ノイズ余裕が小さいと永久に成立しない。

```c
if (in_range) { if (++cnt >= N) ok = 1; }
else          { cnt -= 8; if (cnt < 0) cnt = 0; }
```

許容幅は**実測ノイズの 3 倍以上**取る。実測せずに決めると、たいてい狭すぎる。

## 観測できるようにする

商用周波数の系を**瞬時値で観測しても何も分からない**。
デバッガで停止した瞬間は正弦波のランダムな位相であって、代表値ではない。

### 1 周期ごとの確定値

```c
if (x > x_pk_run) { x_pk_run = x; }
if (++cnt >= N) { x_pk = x_pk_run; x_pk_run = 0; cnt = 0; }
```

最低限これを持っておきたい量：

- 入力電圧のピーク（校正用）
- 電流の最大・最小（ノイズ余裕とモード判定）
- **デューティのピーク**（飽和しているかどうか）
- 電流指令のピーク（指令と実測の比較）

**指令のピークと実測のピークを並べて見られる**ようにしておくと、
「ループが追従しているか」が一目で分かる。追従していなければ、
ゲインではなくフィードバックの経路を疑う。

### 下がらない保持値

デバッガで停止すると制御は止まるが**ハードウェアの PWM は動き続ける**。
電流が制御されずに流れるので、通電中の停止は危険。

「電源を切ってから停止して読む」手順が取れるよう、リセットするまで下がらない
保持値を別に持っておく。

```c
if (x_pk > x_hold) { x_hold = x_pk; }
```

次の測定点に進む前に、デバッガから 0 を書き戻す。

### 障害カウンタ

保護が働いた回数を積算しておくと、「1 回きりの事象」か「周期的に起きている」かが分かる。
これが分かるだけで、ノイズか本物かの判断がつく。

```c
uint16_t ocp_hits;    /* ソフト過電流がしきい値を超えた回数 */
uint16_t cmp_hits;    /* 比較器が反応した回数 */
uint16_t pol_err_hits;/* 極性判定が怪しかった回数 */
```

## 壊れ方のカタログ

症状から当たりをつけるための対応表。

| 症状 | 疑うところ |
|---|---|
| デューティが上限に張り付いて動かない | 符号反転（正帰還）／フィードバックが届いていない／積分器の巻き上がり |
| 実電流が指令の数倍 | 同上。または DCM で 1 点サンプリングが平均を表していない |
| 出力電圧がある値で頭打ち | アンチワインドアップの制限値が構成と不一致 |
| 保護が頻繁に誤作動 | ADC トリガがスイッチングエッジ上／比較器がラッチモード／しきい値が動作域に入っている |
| 正負の半周期で挙動が違う | 片側のセンス系が死んでいる／ゲインが非対称 |
| 中間電圧が際限なく上がる | 無負荷で電力を入れている（`Vdc ≒ n·Vo` で追随する） |
| ゲートを有効にした瞬間にサージ | 無効中も積分器を回していた |
| デバッガで停止すると過電流 | PWM はハードなので止まらない。電源を切ってから停止する |
| 保護が一度働くと復帰しない | ハードのラッチをクリアしていない／クリア経路がソフト側にしかない |
| 制御が止まるのにスイッチングは続く | ISR の途中で `return` している |
