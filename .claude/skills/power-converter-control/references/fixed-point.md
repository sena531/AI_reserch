## 設計の鎖を切らない

ゲインを `#define KP 2676` のように**数値で書かない**。
センサ、分圧比、PWM 周期、ADC 分解能のどれか一つが変わっただけで全部ずれるのに、
どこを直せばいいかソースから読み取れなくなる。

物理定数から `#define` の連鎖で導く。浮動小数で書いてよい。
コンパイラが定数畳み込みするので、実行時には整数リテラルと同じになる。

```c
/* --- 測って決める値（実機で校正する） --- */
#define ISENS_V_PER_A   0.200       /* センサ感度 */
#define ISENS_OFS       2015        /* 無電流時の ADC 値 */
#define VLINE_CNT_PER_V 9.83        /* 分圧 + バッファ後の換算 */

/* --- 回路定数 --- */
#define L_H             1.0e-3
#define VDC_V           220.0
#define PERIODmax       9600        /* PTPER */
#define FS_HZ           100000.0

/* --- ここから下は自動で決まる --- */
#define ADC_CNT_PER_V   (4095.0/3.3)
#define ADC_CNT_PER_A   (ADC_CNT_PER_V * ISENS_V_PER_A)
#define FC_I_HZ         3000.0
#define KP_I_PHYS       (2*3.14159265*FC_I_HZ*L_H/VDC_V)
#define KI_I_PHYS       (KP_I_PHYS*2*3.14159265*(FC_I_HZ/5.0))
#define KP_I_CNT        (KP_I_PHYS*PERIODmax/ADC_CNT_PER_A)
#define KIT_I_CNT       (KI_I_PHYS*(1.0/FS_HZ)*PERIODmax/ADC_CNT_PER_A)
```

こうしておくと、センサを 100 mV/A のものに張り替えたとき `ISENS_V_PER_A` の 1 行で済む。

## 単位換算

### 鎖の各環

| 変換 | 係数 |
|---|---|
| 電流 [A] → ADC カウント | `ADC_CNT_PER_A = (2^bits−1)/Vref × 感度[V/A]` |
| 電圧 [V] → ADC カウント | `VLINE_CNT_PER_V`（分圧比 × ADC_CNT_PER_V、実測で決める） |
| デューティ [0〜1] → PWM カウント | `PERIODmax` |

### 電流 PI

```
Kp[PWMcnt/ADCcnt] = Kp[duty/A] × PERIODmax ÷ ADC_CNT_PER_A
Ki·T 項も同じ係数を掛ける
```

### 電圧 PI

出力が「乗算器単位の `Ipk`」なので、換算係数が一段増える。

```
MULCONV   = ADC_CNT_PER_A × 2^SH_MUL ÷ VREC_PK_CNT
Kp_v[内部] = Kp_v[A/V] ÷ VO_CNT_PER_V × MULCONV
```

`÷ VO_CNT_PER_V` は入力側（V → ADC カウント）、`× MULCONV` は出力側（A → 乗算器単位）。
**入出力の両方を換算する**のを忘れやすい。

### 検算のしかた

換算後の値が妥当か、物理的に意味の分かる量で確かめる。

```
定格電流の 1 A 誤差に対して、デューティが何カウント動くか
= Kp[PWMcnt/ADCcnt] × ADC_CNT_PER_A
```

これが `PERIODmax` と同じオーダーなら強すぎ、1/1000 なら弱すぎ。
数十〜数百カウントに収まるのが普通。

## Tustin 増分形 PI

### なぜ増分形か

位置形（積分器を別変数で持つ）だと、飽和したときに積分器だけ別扱いする必要がある。
増分形は出力そのものを保持するので、**出力をクランプすればアンチワインドアップになる**。

### 式

連続系 `C(s) = Kp + Ki/s` を双一次変換（`s → (2/T)(z−1)/(z+1)`）すると

```
u[n] = u[n−1] + A·e[n] − B·e[n−1]
A = Kp + Ki·T/2
B = Kp − Ki·T/2
```

前進オイラー（`A = Kp + Ki·T`, `B = Kp`）より周波数特性の歪みが小さい。
サンプリングが交差周波数の 20 倍以上あるなら差は小さいが、計算量は同じなので双一次でよい。

### 実装

```c
#define SH_I   10
#define KI_A   ((int32_t)((KP_I_CNT + KIT_I_CNT/2.0) * (1L<<SH_I)))
#define KI_B   ((int32_t)((KP_I_CNT - KIT_I_CNT/2.0) * (1L<<SH_I)))

int32_t Ui = 0, Ei = 0, Ei_1 = 0;

Ei = (int32_t)Iref - (int32_t)Ir;
Ui = Ui + KI_A*Ei - KI_B*Ei_1;
Ei_1 = Ei;
/* ここでクランプ（下記） */
Dpi = (int)(Ui >> SH_I);
```

`Ui` は `2^SH_I` 倍された状態で保持する。これが分解能を稼ぐ仕掛け。

## シフト量の決め方

**シフト量は「分解能が上がるから大きいほどよい」ではない。** 四つの制約が上下から挟む。
`scripts/gains.py` が全部計算して表にするので、まずそれを実行して数字を見ること。
ただし**スクリプトの推奨を鵜呑みにしない**。下の (c) と (d) は設計方針によって重みが変わる。

### (a) 下限：積分の死にゾーン ← 見落とすと積分が永久に効かない

一番危ない制約。**偏差 1 カウントあたりの積分の増分**を計算する。

```
積分増分 [PWMカウント/サンプル] = Ki[duty/(A·s)] × T × PERIOD ÷ ADC_per_A
                               = KiT_cnt
```

これが **1 未満になることがほとんど**。たとえば電流ループで 0.055 PWM カウント。

このとき、毎サンプル `u = u + A·e − B·e_1; Dpi = u >> S;` のように計算して
**`u` を毎回シフトして丸めてしまうと、増分が 0 に切り捨てられて積分が一生進まない**。
P 項だけが効く比例制御になり、定常偏差が消えない。

```
必要な小数ビット数 = ceil( −log2(KiT_cnt) )
```

0.055 なら 4.2 bit、0.0085 なら 6.9 bit。

**対策は「アキュムレータをシフトしたまま 32 bit で保持し、PWM レジスタに書くときだけシフトする」。**
増分形の `Ui` を `2^S` 倍のまま持つのはこのためで、単なる分解能稼ぎではない。

```c
Ui = Ui + KI_A*Ei - KI_B*Ei_1;   /* Ui は 2^S 倍のまま保持 */
/* クランプも 2^S 倍の世界で行う */
Dpi = (int)(Ui >> SH_I);          /* 使うときだけ落とす */
```

`S` はこの必要ビット数より十分大きくする。目安は **必要ビット数 + 6 以上**。

### (b) 上限：オーバーフローしないこと

```
|A| × 2^S × |e_max| < 2^31
```

**`e_max` を「定格の偏差」で見積もると足りない。** 異常時には ADC がレールまで振れる。
極性判定の誤り、センサの断線、起動時の過渡で `e` は**フルスケール（12 bit なら 4095）**に達する。
さらに `A·e` と `B·e_1` の 2 項があるので実効の余裕は半分になる。

`e_max` はフルスケールで評価し、**余裕 8 倍以上**を確保する。

### (c) 上限：係数を int16 に収める（16 bit DSC では強く効く）

```
|A| × 2^S < 32767   かつ   |B| × 2^S < 32767
```

これを満たすと**係数が `int16_t` に収まり、dsPIC33 / C2000 の 16×16→32 MAC が 1 命令で回る**。
超えると 32×16 の合成演算に落ちて、ISR の実行時間が倍近くなる。
100 kHz（10 µs）の ISR では無視できない差になる。

**ただし係数だけ int16 にしても効かない。偏差も int16 でなければ 1 命令にならない。**

```c
int32_t Ei;                          /* ← これだと 32x16 の合成演算に落ちる */
Ui = Ui + KI_A*Ei - KI_B*Ei_1;
```

```c
int16_t Ei, Ei_1;                    /* 偏差も int16 にする */
Ei = (int16_t)(Iref - Ir);           /* 差を取ってからクリップして収める */
if (Ei >  ADC_FS) { Ei =  ADC_FS; }
if (Ei < -ADC_FS) { Ei = -ADC_FS; }
Ui = Ui + __builtin_mulss(KI_A, Ei) - __builtin_mulss(KI_B, Ei_1);
```

偏差は本来 ADC フルスケール（±4095）に収まるので int16 で足りる。
**両方が int16 のときだけ `mul.ss` の 1 命令になる。** 生成アセンブリで
`mul.ss` か `mulw.ss` + `mul.uu` かを確認すると確実。

コンパイラ組み込み（`__builtin_mulss`）を使わなくても、両辺が `int16_t` なら
最適化が効いて同じコードになることが多い。確認してから決めればよい。

別の見方：**係数の絶対値が ±1 に収まるなら Q15、超えるなら Q14** という Q フォーマットの判断。
係数が 1 を超えるかどうかは交差周波数で決まるので、**`fc` を少し下げると Q が 1 桁上がる**
ことがある。設計の自由度として使える。

### (d) 増分形の桁落ち：いつ Q30 / 並列形に移るか

```
Ki·T = A − B
```

**積分の情報は、ほぼ等しい 2 数の差に全部入っている。** `A` と `B` を整数化するとき、
それぞれに ±0.5 LSB の丸め誤差が乗り、その誤差が差に直撃する。

```
Ki の相対誤差（最悪） ≒ 1 / (|A−B| × 2^S)
```

`A − B` = 0.0085、`S` = 15 なら誤差 0.36 %。これは許容範囲。
`A − B` が `2^−(S−7)` を下回るあたりから誤差が数 % に膨らむので、そうなったら

- `S` を上げる（ただし (b)(c) と衝突する）
- **アキュムレータと係数を Q30 / int32 にする**
- **並列形（P と I を別々に持つ）に移る** — 差を取らないので桁落ちしない

のいずれかに移る。電圧ループは `T` が大きい（1/f_line）ぶん `Ki·T` が大きくなりやすいので、
電流ループより桁落ちしにくい。危ないのは**電流ループで零点をうんと下げたとき**。

### まとめ

| 制約 | 向き | 効き方 |
|---|---|---|
| (a) 積分の死にゾーン | **下限** | 破ると積分が効かない。最優先 |
| (b) オーバーフロー | 上限 | `e` はフルスケールで評価。余裕 8 倍 |
| (c) int16 MAC | 上限 | 破ると ISR が遅くなる。16 bit DSC では重い |
| (d) 桁落ち | 下限寄り | `A−B` が小さいとき Q30 / 並列形へ |

多くの場合 **(a) が下限 7 前後、(c) が上限 15 前後**を与えるので、その間で
`A·2^S` が int16 に収まる最大値を選ぶ。`S = 14 〜 15` に落ち着くことが多い。

## アンチワインドアップ

### 制限値は「実際に出せる値」

`Ui >> S` が最終的に何になるかで変わる。

```c
/* Duty = D_ff + Dpi : PI は補正分だけ */
lim = (int32_t)(PERIODmax*6/10) << SH_I;
if (Ui >  lim) Ui =  lim;
if (Ui < -lim) Ui = -lim;

/* Duty = Dpi のみ : PI が全域を受け持つ */
lim = (int32_t)DUTYmax << SH_I;
if (Ui > lim) Ui = lim;
if (Ui < 0)   Ui = 0;
```

フィードフォワードの有無を切り替えられるようにするなら、**制限値も一緒に切り替える**。
片方だけ変えると、デューティが途中で頭打ちになる。
エラーも警告も出ないので、波形を見るまで気づけない種類のバグになる。

### ゲートを止めている間は積分も止める

保護、ブランキング、センサ異常などでゲートを殺しているとき、PI を回し続けてはいけない。
「指令は出しているのに電流が返ってこない」状態なので、偏差が正のまま積分され、
**上限まで巻き上がる**。ゲートが復活した瞬間に最大デューティから動き出す。

```c
if (gate_disabled) { Ui = 0; Ei_1 = 0; }
```

### 飽和を観測できるようにする

積分器が上限に張り付いているかどうかは、**外から見えないと診断できない**。
デューティのピークを 1 周期ごとに保持する変数を用意しておくと、
「上限に張り付いている」ことが一目で分かる。

```c
if (Wout > wout_pk_run) { wout_pk_run = Wout; }
if (++cnt >= N) { wout_pk = wout_pk_run; wout_pk_run = 0; cnt = 0; }
```

`wout_pk` が `DUTYmax` のままなら、ループは制御していない。飽和しているだけ。

## よくある落とし穴

### 符号付き・符号なしの混在

ADC レジスタは符号なし、偏差は符号付き。片方のキャストを忘れると、
負の偏差が巨大な正の数になる。

```c
Ei = (int32_t)Iref - (int32_t)Ir;   /* 両方明示的にキャスト */
```

### 中間結果の型

```c
Iref = (int)(((int32_t)Vrec * Ipk) >> SH_MUL);
```

`Vrec` を `int32_t` にキャストしないと、16 bit 同士の掛け算でオーバーフローする。
掛ける前にキャストすること。

### `int` が 16 bit の処理系では、定数式ですら桁あふれする

XC16（dsPIC33 / PIC24）や一部の 8/16 bit コンパイラでは `int` が **16 bit**。
上限は 32767 しかないので、**定数だけの式でも溢れる**。

```c
#define PERIODmax 9600

lim = (int32_t)(PERIODmax*6/10) << SH_I;    /* 誤り */
```

`PERIODmax*6` = 57600 は int16 に入らない。キャストが**括弧の外**にあるので、
`9600*6/10` を 16 bit で計算し終えてから 32 bit に広げている。
57600 は −7936 に化け、`lim` が負になる。アンチワインドアップの上限が負になれば、
PI は何も出力できない。

```c
lim = ((int32_t)PERIODmax*6/10) << SH_I;    /* 正しい */
```

**キャストは「溢れる演算より前」に置く。** 括弧の位置が 1 つずれるだけで意味が変わる。

見分け方：掛け算の中間結果が 32767 を超えるかどうかを、式を読むときに毎回確認する。
`PERIOD × 係数`、`N_VLOOP × 何か`、`ADCフルスケール × 何か` はどれも危ない。

コンパイラは定数式のオーバーフローを警告することがあるので、
**警告レベルを上げて潰しておく**と早期に見つかる。

### 右シフトと除算は違う

負の数の右シフトは処理系定義（多くは算術シフトで −∞ 方向に丸め）、
除算は 0 方向に丸める。**符号付きの値をシフトで割るとき、0 付近で 1 カウントずれる**。
PI の出力など、0 をまたぐ量では影響を意識しておく。

### 定数畳み込みが効いているか確認する

`#define` に浮動小数を書いても、**整数の文脈で使えばコンパイル時に畳み込まれる**。
ただし `(int32_t)` のキャストを忘れると浮動小数のまま実行時計算になり、
ソフト浮動小数ライブラリが呼ばれて ISR が間に合わなくなる。

逆アセンブルまで見なくても、**ビルド後のコードサイズが急に増えたら疑う**。
