# 電力変換器のデジタル制御：設計と実装

スイッチング電源の制御を「紙の上の伝達関数」から「ISR の中で動く整数演算」まで落とし込むための手順書。
物理量で設計して最後に単位換算する、という順序を崩さないことが要点。
最初から ADC カウントで考え始めると、あとでゲインが合わない理由を追えなくなる。

## 進め方

1. 構成を決める（どのループが何を操作し、何 Hz で回るか）
2. 物理量でゲインを設計する（A、V、H、F、秒）
3. **設計を検証する**（位相余裕・ゲイン余裕を計算する）
4. 固定小数点に換算する（ADC カウント、PWM カウント）
5. ISR を書く（順序と符号の規律）
6. 保護を層にする

`scripts/gains.py` が 2〜4 を全部やる。回路定数を渡すと `#define` の数値に加えて、
**シフト量を選んだ四つの根拠**と**位相余裕・ゲイン余裕・遅れ余裕**を表で出す。
手計算して写し間違えるより確実なので、先に実行して数字を見ながら設計を詰めるとよい。

```bash
python scripts/gains.py --preset boost-pfc        # 読みやすい表
python scripts/gains.py --preset boost-pfc --emit c   # ヘッダに貼れる形
python scripts/gains.py --help
```

**ただしスクリプトの出力を鵜呑みにしないこと。** シフト量の選び方は設計方針で変わるし
（16 bit MAC を使いたいか、分解能を優先するか）、遅れの見積もり `--td-ts` は構成依存。
スクリプトは「根拠を並べる」ところまでをやる。**選ぶのは設計者の仕事。**

### 相手に渡すものの形

このスキルも `gains.py` も**こちら側の道具**であって、相談してきた人は持っていない。
回答の中で「`gains.py` で検証した」「`scripts/gains.py --preset ...` を実行すると」のように
**内部ツールを参照しない**。相手にとっては存在しないファイルの話になる。

数値を出すときは**その数値がどこから来るかを式で示す**。相手が電卓や自分のコードで
追えるようにしておけば、道具の有無に依存しない。

```
悪い : SH_I = 15（gains.py の出力）
良い : SH_I = 15
       (a) Ki·T = 0.154 → 小数 2.7 bit 必要 → S ≥ 9
       (c) |A|·2^S < 32767 → S ≤ 13
       → 9 ≤ S ≤ 13 の範囲で分解能を取り 13。ただし fc を 2.5kHz まで
         上げる可能性があるなら、その範囲でも成立する S にしておく
```

**そして必ず散文で答える。** コードやヘッダを添えるのはよいが、
「なぜそうなるか」を文章で説明せずにファイルだけ投げない。
相手が聞いているのはたいてい**判断の根拠**であって、結果の数値ではない。

### 経験則で終わらせない

「交差周波数はスイッチング周波数の 1/10」のような定番は、**遅れを入れて計算すると
位相余裕が 24° しか残らない**ことがある。`gains.py` はこれを警告する。

```
$ python scripts/gains.py --preset boost-pfc --fc-i 10000
  位相余裕 PM  = 23.9 deg   [!] 45deg 未満。fc を下げること
  ゲイン余裕 GM= 3.6 dB     [!] 6dB 未満
  遅れ余裕     = 想定遅れの 0.43 倍まで   [!] 2倍未満
```

係数を出したら**必ず余裕を確認する**。詳細は `references/loop-design.md` の「設計を検証する」。

## 1. 構成を決める

### 平均電流制御（PFC の標準形）

```
Vo ──→[電圧ループ]──→ Ipk ──┐
                            ×──→ Iref ──→[電流ループ]──→ Duty
             |vac| ─────────┘
```

- **内側＝電流ループ**：スイッチング周波数で回す。入力電流を `Iref` に追従させる
- **外側＝電圧ループ**：商用周波数程度で回す。出力電圧を保って「電流の振幅指令 `Ipk`」を作る
- **乗算器**：`Iref = |vac| × Ipk`。入力電流を入力電圧と相似にする＝力率 1 にする仕掛け

電圧ループを速くすると `Ipk` が商用リプルに追従してしまい、`Iref` が歪んで力率が落ちる。
**遅いことが仕様**であって、性能不足ではない。

### 出力電圧の平均化：移動平均が低域通過より優れる理由

出力には 2×f_line のリプルが必ず乗る。これを電圧ループに入れないために、
**窓幅をちょうど商用 1 周期にした移動平均（ボックスカー）**を使う。

```
N = fs / f_line        /* 例: 100kHz / 50Hz = 2000 サンプル */
```

窓幅が周期の整数倍のとき、その周波数とすべての高調波でゲインが厳密に 0 になる。
一次 LPF で同じ減衰を得ようとすると、はるかに大きな遅れを払うことになる。

**代償**：窓幅が電源周波数に固定される。60 Hz 地域で 50 Hz 前提の窓を使うと、
リプルが素通りして電圧ループが揺れる。`f_line` は定数ではなく**設定値**として扱い、
`N` をそこから自動計算する形にしておくこと。

### 位相シフトフルブリッジを後段に持つ場合

伝送電力は位相シフト角 D1（0〜0.5、角度では 0〜180°）で決まる。静特性を D1 について解くと

```
D1 = sqrt( Vo · Llk · Io / ( Ts · Vdc · (Vdc − n·Vo) ) )
```

`(Vdc − n·Vo)` に注目する。**Vdc が n·Vo に近づくと伝送能力がゼロに落ちる**。
裏を返すと、軽負荷では `Vdc ≒ n·Vo` に張り付く。中間電圧は「ブリッジが出力電圧の n 倍に
クランプする」と理解しておくと、動作点の予想が立てやすい。

D1 は固定にしてしまうのが素直。前段の電流ループが電力を決め、中間電圧が自分で釣り合う。
D1 も閉ループにすると、中間電圧のリプルに対して二重に効いて振動しやすい。

## 2. 物理量でゲインを設計する

### 電流ループ

インダクタを操作対象とみると、デューティから電流への伝達関数は

```
P(s) = Vdc / (s · L)          [A / duty]
```

`Vdc` は出力側（昇圧なら中間電圧、降圧なら入力電圧）。PI を `C(s) = Kp + Ki/s` として

```
交差周波数  fc  = fs/20 〜 fs/40      （100kHz なら 2.5〜5kHz）
Kp = 2π · fc · L / Vdc
零点        fz  = fc / 5             （位相余裕を稼ぐ）
Ki = Kp · 2π · fz
```

`fc` をこれ以上上げると、サンプリング遅れとスイッチングリプルで余裕がなくなる。

**注意**：`Vdc` は動作点で変わる。定格の値で設計しておき、立ち上げ時の低電圧では
ループが遅くなることを承知しておく。遅いのは安全側なので問題にならない。

### 電圧ループ

`Ipk` から `Vo` への伝達関数は、出力コンデンサが支配する。

```
P(s) = Vac_pk / (2 · Vo · C · s)     [V / (Ipk の単位)]
```

分母の 2 は、正弦波入力の平均電力が `Vac_pk · Ipk / 2` であることから来る。

```
G0 = Vac_pk / (2 · Vo · C)
交差周波数  fc_v = f_line/10 〜 f_line/25   （50Hz なら 2〜5Hz）
Kp_v = 2π · fc_v / G0
零点        fz_v ≒ fc_v
Ki_v = Kp_v · 2π · fz_v
```

**`C` を変えたら `Kp_v` も比例して変える**。出力コンデンサは試作中に変わりやすいので、
定数を直接書かず `C` から計算する形にしておくと事故が減る。

### フィードフォワード

昇圧なら `Vdc = |vac| / (1 − D)` なので、定常解は

```
D_ff = 1 − |vac| / Vdc
```

これを先に与えると PI は偏差分だけ受け持てばよく、電圧ピーク付近の追従遅れによる歪みが減る。

**ただし `Vdc` を実測していないなら、立ち上げ時は無効にすること。** 定格値（例 220V）を
決め打ちにすると、入力が数 V しかない段階で「220V まで昇圧せよ」という意味のデューティ 95% を
出し続ける。実際の中間電圧は数十 V なので指令として無意味で、PI が積分で押し戻すまでの間に
制御外の電流が流れる。`USE_FF` のような切り替えを用意し、**定格付近で動き出してから有効化**する。

## 3. 固定小数点に換算する

### 単位の鎖をつなぐ

物理ゲインは `duty/A`、実装で欲しいのは `PWMカウント/ADCカウント`。

```
Kp[cnt/cnt] = Kp[duty/A] × PERIOD[cnt/duty] ÷ ADC_per_A[cnt/A]
```

`ADC_per_A` はセンサ感度と ADC フルスケールから決まる。

```
ADC_per_V = (2^bits − 1) / Vref
ADC_per_A = ADC_per_V × センサ感度[V/A]
```

**この鎖を `#define` の連鎖としてソースに書く。** 数値を直接埋め込まない。
センサを張り替えたとき、感度の 1 行を直せばゲインが全部追従する。
コンパイラが定数畳み込みするので実行時コストはゼロ。

```c
#define ADC_CNT_PER_V   (4095.0/3.3)
#define ADC_CNT_PER_A   (ADC_CNT_PER_V * ISENS_V_PER_A)
#define KP_I_CNT        (KP_I_PHYS * PERIODmax / ADC_CNT_PER_A)
```

### Tustin（双一次）の増分形 PI

積分器を別に持たず、前回出力からの増分で書く。飽和の扱いが素直になる。

```
u[n] = u[n−1] + A·e[n] − B·e[n−1]
A = Kp + Ki·T/2
B = Kp − Ki·T/2
```

整数化は `2^S` 倍して保持し、出力時に右シフトする。

```c
#define SH_I   10
#define KI_A   ((int32_t)((KP_CNT + KIT_CNT/2.0) * (1L<<SH_I)))
#define KI_B   ((int32_t)((KP_CNT - KIT_CNT/2.0) * (1L<<SH_I)))

Ui  = Ui + KI_A*Ei - KI_B*Ei_1;
Ei_1 = Ei;
Dpi = (int)(Ui >> SH_I);
```

### `Ui` をシフトしたまま保持するのは、分解能稼ぎではない

ここを誤解して「毎回シフトして `int` で持つ」形に書き直すと、**積分が永久に効かなくなる。**

偏差 1 カウントあたりの積分の増分は `Ki·T·PERIOD ÷ ADC_per_A` で、
**たいてい 1 PWM カウント未満**（典型例で 0.05〜0.15）。毎サンプル `>> S` して整数に丸めると、
この増分は **0 に切り捨てられる**。P 項だけが効く比例制御になり、定常偏差が消えない。
しかもエラーも警告も出ない。

だから **アキュムレータは `2^S` 倍のまま 32 bit で持ち、PWM レジスタに書くときだけ落とす**。
クランプも `2^S` 倍の世界で行う。

### シフト量は四つの制約が上下から挟む

| 制約 | 向き | 破ると |
|---|---|---|
| **(a) 積分の死にゾーン** | **下限** | **積分が効かない**。最優先 |
| (b) オーバーフロー | 上限 | `int32` が溢れる。`e` は**異常時に ADC フルスケール**まで振れる前提で評価する |
| (c) int16 MAC | 上限 | `\|A\|·2^S < 32767` なら 16×16 MAC が 1 命令。超えると ISR が遅くなる |
| (d) 桁落ち | 下限寄り | `Ki·T = A − B` の差に積分情報が全部入る。小さいと Ki 誤差が数 % に |

「分解能が上がるから大きいほどよい」ではない。(a) が下限 7〜9、(c) が上限 13〜15 を
与えることが多く、その間で選ぶことになる。

`gains.py` が四つすべてを計算して、それぞれの与える上限・下限を表示する。
導出と判断基準は `references/fixed-point.md`。

### アンチワインドアップの上限は「実際に出せる値」に合わせる

ここが**最も間違えやすい**。`Ui` の制限値は、PI の出力が最終的に何になるかで変わる。

| 構成 | `Ui` の制限 |
|---|---|
| `Duty = D_ff + Dpi` | `Dpi` は補正分なので ±(定格の 30〜60%) 程度 |
| `Duty = Dpi` のみ | **0 〜 Duty_max の全域**が必要 |

フィードフォワードを無効にしたのに制限を ±60% のままにすると、**デューティが 60% で頭打ちになる**。
昇圧比 1/(1−0.6) = 2.5 倍までしか出ず、出力電圧がそこで止まる。しかもエラーは出ない。
ループが黙って飽和するだけなので、波形を見るまで気づけない。

```c
#if (USE_FF == 1)
    lim = (int32_t)(PERIODmax*6/10) << SH_I;
    if (Ui >  lim) { Ui =  lim; }
    if (Ui < -lim) { Ui = -lim; }
#else
    lim = (int32_t)DUTYmax << SH_I;
    if (Ui > lim) { Ui = lim; }
    if (Ui < 0)   { Ui = 0;   }
#endif
```

**ゲートを止めている間は積分器も止める。** 保護やブランキングでゲートを殺しているのに
PI を回し続けると、「指令は出しているのに電流が返ってこない」状態で積分器が上限まで巻き上がる。
ゲートが復活した瞬間に最大デューティから動き出して、大きなサージになる。

## 4. ISR を書く

詳しい並びと理由は `references/isr-structure.md`。ここでは要点だけ。

### 順序

```
① センシング（ADC 読み出し）
② 極性判定（ヒステリシス付き）
③ 健全性チェック・保護
④ 外側ループ（N 回に 1 回）
⑤ 乗算器 → 電流指令
⑥ 電流 PI
⑦ フィードフォワード加算・クランプ
⑧ ゲート配分
```

③ を ⑥ より前に置く。壊れた入力で制御器を回すと、積分器が異常値を記憶してしまう。

### 符号の規律：ここが崩れると正帰還になる

全波整流された座標で制御するとき、計測電流を極性フラグで折り返す。

```c
if (half) { Ir =  Iin; } else { Ir = -Iin; }
```

**極性フラグが実際の半周期とずれると、負帰還が正帰還に変わる。**
`Ei = Iref − Ir` で `Ir` の符号が逆なら、電流が増えるほど偏差が正に大きくなり、
デューティが上限に張り付いて電流が発散する。

これは「ゲインが高すぎる」とは全く違う壊れ方で、デューティが上限で動かなくなるのが特徴。
対策として**物理的にありえない値を検出する**関門を置く：

```c
/* 昇圧形はダイオードが逆流を阻止するので、整流座標の電流が
 * 大きく負になることはありえない。そうなっていたら極性判定が
 * 間違っている。正帰還になる前に積分器をクリアしてゲートを止める。 */
if (Ir < -NOISE_BAND) {
    pol_err = 1;  Ui = 0;  Ei_1 = 0;
}
```

極性判定とゲート配分は**同じ判定を使う**。別々の条件式で書くと、零クロス付近で
「ゲートは正の半周期なのに電流の符号は負の半周期」という瞬間が生まれる。

### ADC のサンプリング点

**トリガ位置が「電流」の意味を決める。**

- スイッチングエッジの真上は最悪。ターンオンのリンギングを電流値として読む
- オン期間の中ほどに置くと、連続モード（CCM）では平均電流の良い近似になる
- **不連続モード（DCM）では 1 点サンプリングは平均を表さない**。電流は毎周期ゼロから立ち上がって
  ゼロに戻る三角パルスなので、サンプル点がパルスの外に落ちれば 0 と読む。
  ループは「電流が足りない」と判断してデューティを上げ続け、実電流が指令を大きく超える

軽負荷や低入力電圧では DCM に入りやすい。**自分がどちらのモードにいるかを把握してから**
平均電流制御のゲインを論じること。

## 5. 保護を層にする

一つの保護で全部を賄おうとすると、速さとノイズ耐性のどちらかを必ず失う。
**それぞれが得意なことだけをやる 3 層**に分ける。

| 層 | 速さ | ノイズ耐性 | 使い方 |
|---|---|---|---|
| アナログ比較器 | サブ µs | 低い（スパイクを拾う） | **サイクルバイサイクル制限**。ラッチにしない |
| ADC サンプリング＋ソフト判定 | 1 周期 | 高い（サンプル点で平均化） | **ラッチ停止**はこちら |
| 妥当性チェック | 遅い | — | センサ生死、極性、範囲外。制御器にゴミを食わせない |

比較器をラッチにすると、ノイズ 1 発で装置全体が止まる。
サイクルバイサイクルなら該当周期だけ削れて次から復帰するので、保護の役目は果たしつつ運転は続く。

### 段をまたいで止めない

二段構成（前段 PFC ＋ 後段 DC-DC）で、**入力側の過電流で後段まで止めてはいけない**。
中間コンデンサに溜まったエネルギーの逃げ場がなくなって過電圧になる。

正しい動作は「前段を絞って入力を断ち、後段は回したまま中間電圧を出力へ抜く」。

### 妥当性チェックは「連続」ではなく「積算」で

「N 回連続で範囲内なら健全」という判定は、**N の間に単発ノイズが 1 回入ると振り出しに戻る**ため、
ノイズ余裕が小さいと永久に成立しない。アップダウンカウンタにして、外れたときは少し戻すだけにする。

```c
if (in_range) { if (++cnt >= N) { ok = 1; } }
else          { cnt -= 8; if (cnt < 0) cnt = 0; }
```

## デバッグ時に覚えておくこと

商用周波数の系を**瞬時値で観測しても何も分からない**。デバッガで停止した瞬間は
正弦波のランダムな位相であって、代表値ではない。

ピークや平均を**ファームウェア側で 1 周期ごとに確定**させ、それを読む。

```c
if (x > x_pk_run) { x_pk_run = x; }
if (++cnt >= N) { x_pk = x_pk_run; x_pk_run = 0; cnt = 0; }
```

校正用には、さらに「リセットするまで下がらない保持値」を別に持つと、
電源を切ってから安全に停止して読む、という手順が取れる。
